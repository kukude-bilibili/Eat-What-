# 竞品/同类产品调研：菜单库 · 点餐决策 · 校园外卖（2026-09-26）

> 分支：`research/menu-library-competitor` · 上游底稿：`docs/2026-09-26-menu-library-research.md`
> 范围：按用户要求**剔除平台数据接入可行性**（已有结论：平台菜单数据不可合法获取，详见底稿 D 节），聚焦"同类产品怎么组织菜单/店铺/菜品、怎么导入、怎么推荐、商业模式"，并蒸馏优秀产品特点。

## 1. 方法与可信度分级

- **A 级**：官方开发者文档 / 官方产品页（可直接点开验证）
- **B 级**：主流媒体或厂商博客
- **C 级**：应用商店描述 / 第三方评测
- **D 级**：模型既有知识，**未验证**（表格中标"未验证"）
- 检索环境限制：搜索引擎为美区节点，中文产品的一手资料可得性差，D 级占比偏高，已如实标注

## 2. 内部基线（"吃什么"现状）

当前模型是**单层 Dish**：`{name, scenes[食堂/外卖/下馆子], price, spicy, type, tags, meals, blurb}` + 自定义菜（AI 拍菜入库）+ 菜单包分享。**没有店铺/菜单对象**，"来自哪个窗口/哪家店"只存在于 blurb 文案里。底稿 B 节已给出 Shop → Menu → Dish 三层草案。竞品调研以此为对照。

## 4. 优秀产品特点蒸馏（本次调研核心结论）

1. **菜单模型的事实标准 = 分类 → 菜品(SPU) → 规格(SKU)**（美团/饿了么/Toast 三方一致，A 级）。启示：我们缺的是"店铺/菜单"这一上层骨架，SKU 规格暂不需要——三层即够。
2. **菜单内容没有合法捷径**（Yelp API 无菜单、Zomato 关停公开 API、美团/饿了么仅商家侧，A 级）。所有玩家都靠"商家自录 + 用户众包照片"两条腿。启示：AI 拍菜是正确的路，且比 Yelp 的"照片 OCR"更进一步（多模态直接打标签）。
3. **最值得抄的产品动作是 Yelp Menu Vision**：相机对纸质菜单 → OCR → 叠加真菜照片与评价数（2026-04 上线，A 级）。它把"看菜单做决定"做成了实时视觉体验。启示：我们的"到店扫一扫 → 高亮已入库的菜/摇中历史/辣度标签"是天然二期亮点。
4. **决策转盘是玩具坟场**：2007 年的 Wheel of Food 到今天的 Mealite，十几年无大产品（C 级）——纯随机无数据沉淀就没有留存。启示：转盘长在"个人菜库 + 摇饭记录 + 时段/避开"上才留得住人，当前底座方向正确。
5. **校园场景的赢家都是封闭动线 + 小而准的库**（D 级）：一个档口 20 道菜，密度和准确度比广度重要。启示："只摇我们的菜"+ 按窗口/店铺分菜单的产品方向符合场景规律。
6. **菜单结构化数据本身是资产**（OpenMenu 靠卖菜单 API 存活，A 级）。启示：菜单包格式要版本化（已是 V1），它是未来"校园标准"的种子。
7. **大平台的推荐都是"评分+距离+个性化"，没人替用户做"现在这一顿吃什么的即时决策"**（A/D 级综合）。启示：这是本项目的生态位——不是和平台抢交易，是补"决定"这块短板。

## 5. 对"吃什么"的 3 个可落地建议

1. **对象模型升级为 店铺/菜单 → 分类(可选) → 菜品**：按底稿 B 节落地 `MenuLibrary / Menu / Shop`，Dish 加 `menuId`；校园=窗口（弱店铺），校外=店铺（强店铺）。匹配器零改动（只看 Dish 字段）
2. **校外导入复用 AI 拍菜主路径**：进流程先选"校园窗口 or 校外店铺"，识别结果直接挂对归属；店铺骨架（店名/品类/位置）一期手填，高德 POI BYOK 二期接入
3. **借 Menu Vision 做"到店扫一扫"**（二期亮点，低成本高传播）：扫纸质菜单 → 高亮我们库里已有的菜 + 显示辣度/时段/摇中历史标签——正好复用 AI 拍菜的识别管线

## 6. MVP 先做什么

1. **M1 模型重构**：MenuLibrary/Menu/Shop 骨架 + 现有 customDishes 无损迁移（自动归入"我的菜库"）
2. **M2 菜库按菜单分组展示** + 转盘支持"只摇某个菜单"
3. **M3 整库菜单包升级**：包格式带 Menu/Shop 结构（版本化 V2），导入导出通道不变

## 7. 先不要做

- 平台菜单 API / 爬虫 / 链接解析（无合法来源，底稿 D 节已论证）
- SKU 规格、订单、购物车、配送（交易属性，远离工具定位）
- 地图/距离排序进推荐权重（等校外店铺骨架有真实数据再议）
- 多校复制、账号体系、评论 UGC（单校密度未验证前都是提前优化）
- Menu Vision 式实时 AR（识别管线相同但工程量大，M1-M3 之后再评估）
