# 地图 API 接入访谈清单（vibe coding 踩坑预备，2026-09-27）

> 用途：向写过地图项目的同学调研，提前预演 M3（校外店铺骨架：高德 POI BYOK）会踩的坑。
> 结构：①高发问题清单 ②让同学粘贴给他 AI 的现成 prompt ③问同学本人的问题。

## 1. 地图 API 高发问题清单

### 1.1 Key 与安全（vibe coding 最高发）
- **Key 类型选错**：高德一个账号里 Key 分平台（Web 服务 / Web 端 JS API / 小程序 / 原生 SDK）。Web 服务 Key 不能用于浏览器 JS API，反过来也不行。AI 经常给你的代码和你的 Key 类型不匹配。
- **安全密钥（jscode）**：2021-12 之后新申请的高德 JS API Key 必须配合安全密钥使用，AI 常漏。
- **Key 泄漏**：前端代码里的 Key 会被打包进 bundle、提交进 git。没有域名白名单/签名校验的 Key 会被刷量盗用。
- **BYOK 模式**：让每个用户填自己的 Key 时，Key 存哪（localStorage 明文）、怎么提示风险。

### 1.2 配额与计费
- **免费配额**：个人开发者各接口日配额、QPS 与"个人认证 / 企业认证"差异巨大（A 级事实需查当期官方页）。
- **超限表现**：超配额返回特定错误码（不是 HTTP 429），AI 往往不处理这个分支。
- **烧配额模式**：页面每次进入都请求一次周边 POI、没有缓存 → 配额几天烧完。

### 1.3 浏览器与跨域
- **CORS**：Web 服务 REST 接口在浏览器直连的跨域行为各家不同（有的支持 JSONP、有的要代理）。AI 常给"fetch 直连"代码，跑起来报 CORS。
- **加载方式**：JS API 2.0 需要 Loader + 安全密钥；1.4 的老代码网上最多，AI 容易混。

### 1.4 坐标系（隐蔽且经典）
- **GCJ-02（高德/腾讯）vs WGS-84（GPS 原始）vs BD-09（百度）**：定位拿到的坐标和 POI 返回的坐标可能不是一个系，画点偏移几百米、算距离全错。vibe coding 最隐蔽的坑。

### 1.5 接口细节
- **POI 搜索参数**：keywords 与 types（分类码）的区别；翻页限制（高德单页 ≤25 条、翻页深度有上限）。
- **返回结构**：坐标是 "lng,lat" 字符串要 split；字段层级常变版本。
- **逆地理编码**：坐标→行政区/城市，另有配额。
- **定位精度**：wifi 定位误差可达数百米，accuracy 字段要展示给用户。

### 1.6 合规
- 个人 Key 条款限制"分发使用"；小程序 getLocation 需要类目 + 隐私协议声明；前端必须声明采集位置信息。

### 1.7 vibe coding 特有
- AI 混用厂商参数（高德 location 格式 vs 腾讯 vs Google）。
- AI 引用过时版本文档。
- AI 不写错误分支：配额超限/未授权/超时全白屏。
- AI 把 Key "顺手"硬编码进代码并提交。

## 2. 让同学直接粘贴给他 AI 的 prompt（6 条）

1. **报错诊断**：「我在用【高德 JS API 2.0 / 高德 Web 服务 REST / 微信 wx.getLocation】（写清一个），Key 类型是【】，运行环境是【浏览器域名 / 小程序 / Node】。报错原文：【粘贴完整报错】。请先按概率列出 3 个最可能原因，再给最小修复代码。不要更换 API 厂商，不要引入新依赖。」
2. **CORS 判断**：「我要在浏览器（域名：XX）直接调用高德 Web 服务 REST 的 POI 搜索接口。请先回答：它是否支持浏览器 CORS 直连？若不支持，给出 JSONP 和自建代理两种方案的最小实现，并分别说明 Key 暴露面与安全风险。」
3. **坐标系**：「我用 wx.getLocation（或浏览器 geolocation）拿到的坐标，要放到高德地图上标点、并和高德 POI 返回的坐标算距离。请说明两者坐标系是否一致；不一致时给出转换方案（算法或官方接口），并解释偏差来源。」
4. **配额与缓存**：「高德个人开发者【POI 搜索 / 逆地理编码】当前的日配额与 QPS 是多少（以官方最新页为准，给链接）？我的页面每次进入请求一次周边。请设计最小缓存策略（localStorage + TTL + 超限错误码识别），并列出配额超限时接口返回的具体错误码。」
5. **Key 安全**：「我的地图 Key 会被打包进前端并公开访问。请给出：①域名白名单怎么配 ②是否需要数字签名（securityJsCode）③如果改成 BYOK（每个用户填自己的 Key），前端存储与提示该怎么做才是相对安全的。」
6. **复盘**：「在这个地图项目里，你实际踩过的最大的 3 个坑是什么？每次的报错原文、你当时的错误假设、最终怎么修的。能给当时的代码片段/diff 最好。」

## 3. 你本人问同学的问题（人肉经验，比 AI 可信）

1. 你的 Key 是个人认证还是企业认证？每个月真实消耗多少配额、有没有被刷过？
2. 坐标系你踩过吗？最后的转换方案是算法还是接口？
3. 浏览器直连 REST 还是你自建了代理？代理部署在哪、花了多少钱？
4. 如果重来一次，你会在动手前先确定哪三件事？
5. （给我们带话）高德 POI 搜索返回的"附近餐饮"，字段够不够做店铺卡片（营业时间/品类/人均有没有）？
